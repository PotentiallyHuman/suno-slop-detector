## What broke
Suno replaced the `/create` lyrics `<textarea data-testid="lyrics-textarea">` with a
Lexical rich-text editor (plus a separate "co-writer" prompt box for "improve this
section / write another verse"). The old selector matched nothing, so the extension read
`""` and showed nothing on the create page.

New structure (captured click-only via Brave "Save page as… → Webpage, Complete";
Ctrl+S is hijacked by Suno):
```
div[contenteditable="true"][role="textbox"][aria-label="Lyrics editor"][data-lexical-editor="true"].lyrics-editor-content
  p.lyrics-paragraph > span[data-lexical-text]   one <p> per line
  p.lyrics-paragraph > br                        blank line
textarea[data-cowrite-input][aria-label="Cowriter prompt"]   NOT the lyrics — skipped
#lyrics-editor-char-count (sr-only) "N of 5000 characters used" — Suno's real state
```

## The fix (`src/content.js` only; manifest = version bump)
- `getCreateBox()` — visible Lexical editor first (dialog preferred), legacy textarea as
  fallback, co-writer box excluded.
- `readBoxText()` — walks the `<p>` blocks (never `innerText`, which double-spaces).
- `setCreateBoxText()` — three write routes, each verified on a timer:
  1. synthetic `paste` ClipboardEvent (Chromium takes it);
  2. `delete` + per-line `insertText` / `insertParagraph` (Firefox ignores a scripted
     paste's clipboard data — found live, would have merged all lines into one paragraph);
  3. whole-text `insertText` (last resort).
  Failure → panel says so and drops the undo entry instead of claiming an edit.
- `data-hz-write` attribute on our own panel root records which route ran (paste / lines /
  inserttext / failed) — read it from a saved page when debugging.
